2025 – 2026Data engineering

Enterprise Master Data Migration & Cleansing

Infineon Technologies · Master Data Developer

The problem

Engineering master data is spread across many system classes and worldwide sites. The same part could exist as several slightly different records, which breaks reports and creates rework for teams that need one single truth.

What I did

Built PL/SQL that consolidates those records: staging tables hold candidate duplicates, a MERGE procedure keeps one “golden” record and repoints the rest, and every change is logged so it can be traced. Around it I refined the ETL and data-warehouse flow with validation before load and clear error handling, moved repeat ticket work into KNIME workflows, and supported SAP-side migration and reporting. Releases went out weekly through Jenkins across DEV, INT and PROD.

30%leaner workflow (SAP projects)
50%less time on repeat tickets
Weeklyreleases, 3 environments

Stack

  • Oracle PL/SQL
  • Oracle DB
  • ETL
  • Data warehouse
  • SAP
  • KNIME
  • Jenkins
  • Azure DevOps
  • C# .NET

Internal enterprise system, so there are no screenshots. The description explains the approach instead.

2024 – 2025Machine learning · Data

Network Fault & Internet Speed Prediction

TM Research & Development · Data Science Intern

The problem

Network faults were handled after customers complained. The data to see problems coming already existed (access network logs, termination logs, CTT records, speed tests) but it was too messy to trust.

What I did

Cleaned and reconciled thousands of records across the sources, then built Random Forest Regression and LSTM time-series models to predict speed drops and faults. Results went into Power BI and Python dashboards reviewed weekly. I also automated data extraction with Selenium Robot Framework and supported the OracleDB to MariaDB migration.

2024 – 2025Deep learning · Web app

Breast Cancer Prediction using HoverNet

UKM · Final Year Project

The problem

Reading histopathology slides means counting and classifying cell nuclei by eye: slow, tiring and inconsistent. A model can give the pathologist a fast second opinion.

What I did

Implemented the HoverNet framework, which predicts distance maps alongside segmentation so touching nuclei can be separated, trained on the PanNuke dataset. I wrapped it in a Django web app where a user uploads a slide image and gets an overlay and counts per class, with results stored in MySQL.

2-in-1segmentation + classification
Web-basedno ML setup for users
First Classdegree outcome

Real-Time Face Mask Detection (YOLOv8 & OpenCV)

Personal project

The problem
